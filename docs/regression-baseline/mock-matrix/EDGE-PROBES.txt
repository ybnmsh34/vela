### PROBE 1 — a request body larger than the server's 8 MiB cap
The server declares a MAX_BODY_BYTES guard that is supposed to answer 413
with code invalid_json. This is what a client actually observes.

$ curl -sS -H 'Expect:' --data-binary @9.4MB.json http://127.0.0.1:8201/v1/chat/completions

FINDING: over the cap there is NO HTTP RESPONSE AT ALL — the socket is reset.
The 413 branch is unreachable: readBody() calls request.destroy() in the same
turn it rejects, so the error response cannot be written. Under the cap the
same request is answered properly. The server survives either way, and logs
nothing, so the failure is silent on both ends.

### PROBE 5 — tools offered with tool_choice:"none" on a no-tools endpoint
{
  "error": {
    "message": "`mock-small-local` does not support tools",
    "type": "invalid_request_error",
    "param": "tools",
    "code": "tools_not_supported"
  }
}
http_code=400
FINDING: refused, even though the caller explicitly asked for no tool use and
the turn could have been answered as plain prose. Over-rejection: a consumer
that always attaches its tool catalogue is locked out of this endpoint even
for turns where it wants none of them.
