GATE M Part 1 (Phase B2) — profile: mid-local — case 20-sibling-surfaces-x-endpoint-text: the string-bearing fields on the SUCCESS path, held to B2's standard
================================================================================

PURPOSE   Executor's pick. B2 closed `ProviderError`. `ChatResponse` crosses the same IPC boundary and has three string fields nobody has audited, for one reason: they live on the success path, and four rounds of security work all started from an error.
SUBJECT   all three shipping adapters
ENDPOINT  one purpose-built loopback peer per adapter, real TCP
HONESTY   VERIFIED-BY-FAKE. The endpoint is a deterministic mock; no model produced
          any byte below. Nothing here is evidence about a real model.

  THE THREE FIELDS:
    Degradation::StructuredOutputMismatch { detail }   documented as Vela's own words
    SchemaMismatch { path, detail }                    path from the USER's schema
    ToolCallOutcome::Malformed { raw_arguments }       endpoint text, ON PURPOSE
  The third one is not a defect and this case does not treat it as one. It asks
  whether the deliberate carry is BOUNDED, whether it stayed in its own field, and
  whether any of it reached the error surface.
