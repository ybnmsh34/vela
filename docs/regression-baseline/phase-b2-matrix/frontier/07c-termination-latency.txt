PURPOSE   MEASURED-1 sharpened: the turn must end in single-digit milliseconds, not merely inside the 5 s a naive [DONE]-driven consumer hung for — and it must do so on the path a configured user actually runs.
SUBJECT   Vela's own provider stack (vela-providers::OpenAiCompatibleProvider)
ENDPOINT  tests/harness/mock-provider, profile `frontier`, a real OS process on loopback
HONESTY   VERIFIED-BY-FAKE. The endpoint is a deterministic mock; no model produced
          any byte below. Nothing here is evidence about a real model.

  Five identical streamed turns per arm. The endpoint is the same OS process
  throughout, so the spread below is this container's scheduling noise and nothing
  else. `hostile` never sends [DONE] and `small-local` never sends usage though it
  accepted `include_usage`: both are the shapes that hung the recorded consumers
  for 5 s.
  ROUND 4. This case used to have one arm, built with `Auth::None`. An empty
  credential set means an empty `Scrubber`, and `BodyStream::next_chunk` takes a
  short-circuit when the scrubber is empty: no copy, no carry buffer, no scan. The
  medians it published were therefore medians of a path that does not run once a
  user configures a key — offered, implicitly, as the latency evidence for the
  redaction they never touched. The CREDENTIALED arm below is the one the
  single-digit claim is now made about; the uncredentialed arm is kept beside it so
  the cost of redaction is visible rather than asserted.
