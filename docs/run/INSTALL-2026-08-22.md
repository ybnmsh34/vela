# The first real install — 2026-08-22

**Operator installed `Vela_0.1.0_x64-setup.exe` on the real machine, outside the container.**

**Result, in the operator's words: "it's a mess."**

No further detail was captured. The project was stopped immediately afterwards, so no screenshots,
no specifics, no list of what was wrong. That absence is itself recorded here rather than papered
over — a future session must not read this file as though the problem is known.

## Why this one sentence outranks everything else in the run

Twelve of eighteen tracks were sitting at **CAPPED-PASS**, failing on nothing but `LADDER`, waiting
on exactly this install. Every one of them was graded `dev-clicked` or `test-bites` — real, verified,
and one rung below the bar that requires an installed app driven as a user drives it.

The install happened, and the answer is that the installed product is a mess.

**So the cap was not a formality.** The run's own ladder said `dev-clicked` is "real progress, not a
pass", and this is the evidence that the distinction was worth defending: a suite of ~2,450 tests, a
green ten-gate pipeline, seven rounds of adversarial grading and 3,000-plus measured claims did not
predict what the thing looks like when a person installs it and opens it.

That is not a failure of the work. It is the finding the ladder existed to produce, arriving exactly
where the ladder said it would — at the rung nobody had reached.

## What this means for the grades in this repository

- **No grade above `dev-clicked` is claimed anywhere, and none should be.** The twelve CAPPED-PASS
  tracks keep that status: it means "everything measurable from inside passed", which is true, and
  it does **not** mean the product is good.
- **The `dev-clicked` evidence was flattering.** A dev binary against a Vite dev server, CDP-
  dispatched events and substituted app-data agreed the surfaces worked. The installed build does
  not agree. Whatever the difference is, it lives in the three substitutions the ladder names.
- **`docs/run/BLOCKER-ladder.md` is now resolved as a blocker and reopened as a finding.** The
  question is no longer "can anyone install it" — someone did — but "what is wrong with what they
  got", and nothing in this repository answers that yet.

## What a future session should do first

Not fix anything. **Get the detail this file does not have**: install on a clean machine, open it,
and write down what is actually wrong — with screenshots, at 100% and 150%, light and dark. Only
then decide what it means.

The one thing that would be a mistake is to guess from here. Seven rounds of this run were spent
proving that a claim is worth exactly the bytes someone read to support it, and the only bytes
anyone has read about the installed product are the two words above.
